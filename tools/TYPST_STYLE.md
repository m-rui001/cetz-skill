# Typst 代码风格标准（语料仓库）

适用于 `figure-as-code`、`physics-typst-corpus`、`math-tex2typst`、`arxiv-stem-zh-corpus`。
目标：源码可读、可维护、可复查，不改变正文与排版结果。所有改动以 `typst compile` 通过为准。

## 1. 空白与文件

- UTF-8 无 BOM，LF 换行，文件末尾恰好一个换行。
- 缩进 2 个空格，禁止 tab、行尾空白。
- 块内最多 1 个连续空行；顶层两个块之间最多 2 个。
- 代码行 ≤ 120 字符；正文段落按句子断行，不按显示宽度硬折。

## 2. 文档骨架

顺序固定：`#import` → 页面/字体/公式设置 → 辅助函数 → 标题与摘要 → 正文 → 参考文献。

- 所有 `#set` / `#show` 只在文件顶部集中出现；正文中途不得再出现。
- 同一个属性只设置一次（`page`、`text`、`math.equation`、`heading`…）。
- 只用实际用到的 import；删除未使用的 import。
- 多次出现的字号、边距、字体写成具名常量（`#let body-size = 10.5pt`），不在正文重复字面量。

## 3. 数学

- 行内公式：单符号 `$x$`；多符号 `$a + b$`，运算符两侧留空格。
- 使用 Typst 语义符号（`alpha`、`plus.minus`、`arrow.r`、`lt.eq`），不写 Unicode 近似字符。
- 行间公式独立成块；只有被 `@eq-...` 引用的公式才编号。
- 禁止裸 LaTeX 命令（`\frac`、`\begin{...}`、`\pi`），`\{`/`\}` 仅用于字面花括号。

## 4. 命名与结构

- 标签一律 kebab-case，按类型前缀：`fig-`、`tab-`、`eq-`、`sec-`、`thm-`。
- 引用只用 `@label`，不手写「图 N」「式 (3)」。
- 辅助函数 kebab-case；除数学变量外不用单字母全局名。
- 同一宏/函数在仓库内只定义一次；共享宏集中在 `macros.typ` 并 import。
- 删除未使用的 `#let`、未使用的参数、不可达的 `.typ` 文件。

## 5. 注释

- 注释解释「为什么」，不重复「做了什么」。
- 注释掉的旧代码整段删除，不留尸体。
- 代码注释统一英文；正文里的中文说明保持原语言。
- 每篇顶部不重复同一段模板注释；仓库级约定写进 README，不写进每篇。

## 6. 图表与间距

- `figure()` 必须带 `caption:` 和 `kind:`；caption 标点一致（中文全角、英文半角）。
- 图片路径必须相对，禁止绝对路径。
- 手动 `#v()`/`#h()` 只用于确有需要的微调；同一文件里的间距值保持一致，禁止用连续空行代替。

## 7. AI 代码痕迹（重点清理）

- 每篇都出现的同一套 banner 注释、同一段「说明」块。
- 对显然的代码逐行注释（`// set page`、`// import cetz`）。
- 为不存在的情况写防御分支、重复兜底。
- 大段结构一致到可以互换的章节模板；应服从论文自身结构。
- 变量名/注释里出现「这里我们」「需要注意的是」等叙述腔。

## 8. 验收

- `typst compile` 0 error；页数与改动前一致，除非风格修复本身修正了排版错误。
- 数学与正文文本 diff 只应包含空白、符号写法、注释和结构移动；不得增删事实、数字、公式项。
- 每个仓库提交前跑 `python -X utf8 tools/compile_all.py`（或该仓库等价脚本）。
- 大规模改写逐文件记录：路径、改动类别、编译结果。

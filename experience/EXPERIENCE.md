# 插图 → CeTZ 转换经验总结

持续更新的经验文档。每批次转换的逐图结果见各批次目录下的 `RESULTS.md`
（各批目录与完成状态见下方「批次记录索引」）。

## 工作流（已验证可行）

- 图源与编号：Fleisch《向量与张量》EPUB 的真实解包路径是
  `E:/EPUB/work/reocr_stage/A Students Guide to Vectors and Tensors*/render/*.epub`，
  按 `sorted()` 文件名共 **97** 张，接触表 `work/EPUB-SHEET-1.png`（1–48）、
  `work/EPUB-SHEET-2.png`（49–97）。batch1–22 用的 1–76 旧编号来自另一份不完整解包，
  已作废；batch23 起一律用新编号（详见 `work/batch23/RESULTS.md`）。

1. 取图：EPUB 解包图 / PDF 提页图往往混入整页或纯文字页，先用 PIL 按
   版面比例裁剪出插图区域（`src/` 目录），再人工目视筛掉纯文字页。
2. 写 CeTZ（`typ/` 目录），固定模板头：
   `#set page(width: auto, height: auto, margin: 12pt)` +
   `#import "@preview/cetz:0.4.2": canvas, draw`。
   page 设 auto 才能导出紧凑 PNG，便于和原图并排目视比对。
3. 编译：`typst compile x.typ x.png --format png --ppi 200`。
4. 视觉比对：Read 原图与编译 PNG，逐项核对元素清单（点、线、弧、标签、
   虚实线、箭头方向）。结构齐全、布局同拓扑即通过；标签错误或元素缺失
   则重试；重试 2 次仍不像则放弃并记录原因。

## CeTZ 0.4.2 语法坑（实测）

- `draw.arc` 的第一个位置参数是**弧的起点（弧上的点）**，不是圆心！
  源码 `shapes.typ`：`sector-center = position - r*(cos start, sin start)`。
  画"以 C 为心、半径 r、从 a 到 b"的弧要写
  `draw.arc(C + (r*cos(a), r*sin(a)), radius: r, start: a, stop: b)`。
  误传圆心会得到一个偏移且缩小观感的弧（batch1 fig2 第一次失败原因）。
- `arc` 的角度参数是 `start` / `stop`（或 `delta`，三选二），**没有 `end`**。
- `$bar(x)$` 不是上横线重音，`bar` 是竖线符号，会渲染成 |x|。
  上横线用 `$overline(Z)$`（batch1 fig2 第二次失败原因）。
- 虚线：`stroke: (dash: "dashed")`；箭头：`mark: (end: ">")`，均可靠。
- `draw.bezier` 的位置参数顺序是 **(start, end, ctrl1, ctrl2)**——第二个
  位置参数是终点，不是控制点！传错会得到折线/回环（batch2 fig5/fig6
  第一次失败原因）。弯曲引线箭头用 bezier + `mark: (end: ">")` 效果好。
- 没有 `draw.ellipse`；椭圆用 `draw.circle(c, radius: (rx, ry))`。
- 向量箭头重音是 `$arrow(A)$`；`$vec(A)$` 是矩阵/向量函数，渲染成
  圆括号 (A)！`hat`/`arrow` 才是重音函数（batch3 fig9/fig10 首败原因）。
- 花括号（underbrace）无原生件：用一条下凹 bezier 近似，放在被标注
  线段正下方即可骗过目视比对。
- 任意填充多边形：`draw.polygon` 只画正多边形（第二参数是边数），
  也没有 `draw.path`；用 `draw.line(p1, p2, ..., close: true, fill: 色)`。
  灰度面用 `luma(150~205)` 区分朝向（batch4 fig11 验证）。
- 放弃案例：斜投影 3D 实体（1/4 圆柱）的曲面凸向靠目测难定，两次
  重试仍镜像相反就放弃（batch4 fig12）。立方体这类全平面实体可转。
- 抛物线/穹顶轮廓：三次 bezier 控制点取 ±0.33*跨度、反向偏移约 1.45*矢高
  即可近似 y=x² 型曲线（batch2 fig5/fig6 验证）。
- 实心点用 `draw.circle(p, radius: 0.07, fill: black, stroke: none)`。
- 标签：书体点名为数学斜体，用 `$Z_2$`、`$overline(Z)$`、`[Z#sym.prime]`；
  方位用 `anchor: "north" / "south-west" / "east"` 等微调。
- `content(..., [Z_1])` 的方括号是 markup，下划线会原样输出 "Z_1"；
  下标/重音一律包进 `$...$`（batch5 fig16、batch6 fig20 两次踩坑）。
  素数撇在 math 里直接写 `$Z_2'$` 即可，不必 `#sym.prime`。
- 凡"点落在两条线交点上"的坐标必须解析求解（联立直线方程），目测必飘
  （batch6 fig19 首败原因）。圆由三点定时用外接圆公式现算圆心半径。
- Typst 脚本没有 `**` 幂运算符，写 `*` 连乘，否则 `expected expression`
  （batch10 fig31 编译失败原因）。
- 花括号/手绘引线 bezier 的控制点必须贴近弦（偏移 ≤0.3 单位）；偏移 1 单位
  以上会画成大回环弧，视觉完全走样（batch10 fig31 首败原因）。
- 成组重复元素（8 个径向箭头等）在 `canvas({})` 里直接写 `for i in range(8)`
  + `calc.cos/sin`，比手写 8 遍短且不会漏项；箭头要落在射线中段时，
  单独画一条 `line(0.62u, 1.05u, mark:(end:">"))` 叠在完整射线上。
- 两直线在图外相交的构造，端点要一并延长过交点，否则拓扑对但明显失真
  （batch9 fig28 首败原因）。
- 标签落点要代入所在直线方程验算，不能只看大致方位：batch11 fig34 的
  ẽ₂/(4,0)/A 三个标签 y=0.3 恰好压在 A 箭杆（y=0.3x）上，统一移到轴下方才过。
- 斜投影立方体：三条基向量写成元组 + `V(i,j,k)` 现算 8 个顶点，
  三面分别 `line(..., close: true, fill: luma(140/180/215))`；
  重复的切向小箭头封装成局部函数 `(p,a)=>line(...)` 可省一半代码（batch11）。
- `draw.content` 默认把文字以锚点为**中心**定位，不是左下角。长标签会向左压到
  大括号/坐标轴上。左对齐写 `anchor: "west"`、右对齐 `"east"`，可一次消掉大部分
  "标签碰撞"重试（batch12 fig38/39）。
- 曲线上的方向箭头不要用"短线段 + mark"，那根直段会露出曲线变成一根刺；
  改在切点画实心三角 `line(p1,p2,p3, close: true, fill: black, stroke: none)`
  （batch12 fig37 磁场环）。透视圆环 `circle(c, radius:(rx, rx*.28))`，
  左右极点切线竖直：左端箭头朝下=出纸面、右端朝上=入纸面，与右手法则一致。
- 同一位置上下成对的标签（如 m₃/m₄）必须按锚点贴到目标点：`anchor: "east"`
  使文字右边缘对齐点、`"west"` 使左边缘对齐点；用默认中心锚点"估个方向"会
  漂到别的线上（batch13 fig42 唯一一次重试）。
- Typst 数学模式容忍**不成对括号**，`$(x_"end" - x_"start",` 可分三行写，
  用来复刻原书跨行的坐标标签（batch13 fig41）。
- 角弧成对使用即可画"旋转坐标系"：`arc((r,0), radius: r, start: 0deg, stop: θ)`
  与 `arc((0,r), radius: r, start: 90deg, stop: 90deg+θ)`；θ 用 `calc.cos/sin`
  单位向量驱动，虚轴与角弧自动同步（batch13 fig40）。
- **Typst 数学不接受 LaTeX 反斜杠转义**：`$\theta$` 直接报
  `unknown variable: heta`。写 `$theta$` / `$hat(e)_r$` / `$Gamma^r_{r theta}$`
  / `$frac(1, r)$`。属编译期错误，一次 compile 即暴露（batch14 fig43）。
- `arc` 和 `bezier` 同样支持 `mark: (end: ">")`：旋转角大弧、注释弯曲箭头
  都能自带箭头，不必再叠一小段 line 补箭头（batch14）。
- 斜投影分量：分量 = 点积 `A·û`，垂足 = `(A·û)*û`；分量为负时垂足自动落到
  负半轴，公式无需分支（batch14 fig44 (b) 零重试）。
- 曲线类图改用「解析参数式 + 折线采样」：`px(t)/py(t)` 两个闭包，21 点喂一条
  `line(...)`，切向量 `(dx, dy(t))/calc.sqrt(..)`，点/切线/曲线恒等，零手调
  （batch15 fig46）。圆圈编号 = `circle(p, radius:.19, fill: white)` + 同点
  `content`；标签当 content 实参传进闭包 `tag((0,0), [4])`，别在 math 里拼 `#$#`。
- 一条射线两段画（外段定端点箭头、内段 `line(.85u,.5u)` 或反向定内圈箭头），
  一个布尔参数即可生成 (a)/(b) 两个反向场图（batch15 fig48）。
- EPUB 内嵌图本身可能被裁切（idx 20 左半 panel 丢失）：源图先确认子图完整，
  缺块直接换候选，不靠猜补画。同一张图第二次遇到（batch16 又撞上 idx 20）
  仍要按拒绝处理，别重做筛选。
- Typst 数学里 `Delta(theta)` 会照字面渲染成 Δ(θ)，要 Δθ 必须写 `Delta theta`；
  同理 `theta_1` 之类下标不受影响，只有"符号+括号"这种写法会多出括号（batch16）。
- 语义看不清的原图：按顶点各裁一小块放大 5 倍逐个 Read，数清每个角上有几个
  箭头，就能唯一确定首尾相接顺序（batch16 fig51 靠这个从"画错一版"翻正）。
- 图里那条"顺带经过几点"的外接大弧，用三点外接圆公式解出圆心与半径再喂 `arc`；
  `Uy` 第二项必须是 `(ax - cx)`，写成 `(cx - ax)` 会得到完全不相干的圆——
  解完后代回验证三点到圆心距离相等再落笔（batch16 fig51）。
- 对照类双面板（平行投影 / 垂直投影）：两面板要交换粗细主次——(a) 里合矢量 A 粗、
  分量细，(b) 里两个投影分量粗、A 细；且 (b) 的虚线是从两分量尖各画一条平行于
  另一轴的线补成平行四边形，交点越过 A 的尖（表示"加起来不是 A"），
  不是从 A 尖向轴作垂线（batch16 fig49，第 2 次重试才改对）。
- 标签字号固定、几何可缩放：带长文本的图起手就把整体尺寸放大到
  1 单位 ≈ 2~3 倍字号宽，否则第一版必然压字（batch17 fig53 首版全挤在一起，
  坐标整体 ×1.7 后一次通过）。
- 立体点位图优先"量原图"而不是套斜投影公式：书里的三维图常经手绘调整，
  原点往往不在底面图形中心，硬套公式反而不像；按像素反解屏幕坐标直接照搬（batch17 fig53）。
- 放大镜/loupe 类图（小圆 → 大圆的放大锥）：小圆画在曲线上、大圆另定心，
  两条虚线连两圆上下边缘附近即可，不必真求公切线（batch17 fig54）。
- `dash: "dotted"` 与 `"dashed"` 可在同图共存，细点线画斜边、虚线画放大锥，
  视觉区分度足够（batch17 fig54）。
- 代码模式里 `[str(t)]` 会照字面渲染成 "str(t)"，markup 内回评代码要写
  `[#(str(t))]`；刻度数字循环标签必踩（batch18 fig56）。
- 场图箭头阵：方向取 `(k*tx, 1)` 归一化，k≈0.75 才有原图的扇开感（k=0.42 看着
  像平行箭）；两层 `for` + 尾点纵向偏移 `-0.3*tx` 造斜排网格（batch18 fig57）。
- 极坐标双基：切向基 = `(-ur.y, ur.x)`，与径向基共用同一个点作起点，
  一次算对不用手调（batch18 fig55）。
- CeTZ 0.4.2 没有圆角矩形：`rect` 只收两个角点、无 `radius:`，也不存在
  `rounded-rect`。手写时**四条边的偏移轴最容易搞反**——顶/底边沿法向 n 整体
  偏移 `±rr*n`（两端同向），左/右边沿 u 偏移 `±rr*u`；角弧就是四个 90° 象窗
  `[a,a+90] [a+90,a+180] [a+180,a+270] [a+270,a+360]`，分别对应角
  `(1,1) (-1,1) (-1,-1) (1,-1)`，弧起点 = 角心 + `rr*(cos st, sin st)`。
  偏移轴写反会得到"四瓣内凹花"（batch19 fig59，耗 3 次才修好）。
- 语义拿不准时先写 10 行的 `probe.typ` 单独验证（同一弧画三种传法 + 虚线参考圆），
  一次编译即可定死 `arc` 的 position/角度语义，比在主图里反复试快得多（batch19）。
- `mark: (end: "<")` 是在**终点**放一个指向起点的 "<" 标记：想让箭头反向不用交换
  `line` 的两端点，换标记字符即可。闭合环四条边按同一顺序写、只换字符，
  一个布尔参数就能出 (a)/(b) 两个环向版本（batch21 fig65）。
- 右向大括号 = 两条 bezier 在中间点拼成尖：上下两段各自的两个控制点都取
  同一 x（略大于端点 x），尖点 x 再往外一点；单条弧线只会看成 "("（batch21 fig64）。
- 波浪引线 = 一条 bezier，两个控制点分居弦的两侧（先同侧再异侧即成 S 形）。
- 环线/框类元素若在原书里是粗线，几何尺寸和线宽要一起放大：只加粗不放大，
  仍会读成"坐标轴上的小记号"（batch21 fig65 唯一一次重试）。
- 带长文本的图，先按"文字宽度 / 几何宽度"定比例再画几何：原书里
  "Current-carrying" 约占椭圆带宽度的 0.68，据此反推几何上限；
  字号不动、只缩几何，一次定对，否则第一版必然像"小图配大字"（batch20 fig62）。
- 扁椭圆（`circle(c, radius:(rx, ry))`，ry 只有 rx 的 1/4 以下）的极值处
  **不要用 `mark: (end: ">")`**：短弧段比箭头标记还短，会画成悬在曲线外的大三角。
  改在左右极值点直接放实心小三角，方向略向外倾（如 `(.58, .81)`）即可
  （batch20 fig62 第 2 次重试）。
- 密集箭头阵：行距取箭头周期的 0.5~0.6 倍才像"场"，行距大于周期会读成刻度；
  书里的粗箭头是实心三角头，用 `line(p1,p2,p3, close:true, fill:black, stroke:none)`
  + 截短的箭杆，比 `mark` 的空心 V 忠实得多（batch20 fig63）。
- Typst 数学里 `$vec(A)$` **不是**矢量箭头，而是向量括号函数，渲染成 `(A)`；
  图上带箭头的矢量标签一律写 `$arrow(A)$`（`arrow(L_5)` 会把下标一起罩住，
  与原书排版一致）。同类能编译的还有 `accent(A, arrow)`、`attach(A, t: arrow.r)`、
  `A.arrow`，但只有 `arrow(A)` 形态正确；`vec(A, delim: none)` 直接报错。
  四个候选塞进同一个 `probe.typ` 一次编译定死，胜过在主图里猜（batch22 两图各耗 1 次）。
- 栏号 `(a)(b)` 用纯文本 `[(a)]`；写成 `[$(a)$]` 会渲染成斜体数学体，
  与原书罗马体不符（batch22 fig69）。
- 垂直关系不要靠量像素：已知 `r=(x,y)` 时 L 取 `(-y,x)/|r| * len`，
  反解出的箭头终点与原图误差 <0.05 单位。先解析后校像素，比重复微调坐标省一轮
  （batch22 fig68）。
- "同一符号两种状态"的成对图元（⊗ 与 ⊙）把外圆半径固定成同一个值（.19），
  只换内部（对角线 / 实心点），才会被读成一套符号（batch22 fig68）。
- 平移相加类图（C=A+B）：虚线平移矢量的终点必须与 C 的终点取同一个坐标，
  两个箭头叠在同一点正是原书样式；各自估像素会画出两个错开的头（batch22 fig69）。
- 原书的长划虚线不是 `dash: "dashed"`（太密，像点线）：写
  `(dash: (array: (9pt, 6pt)), thickness: 1.3pt)` 才和书里一致（batch23 fig72）。
- 弯曲引线箭头的朝向由 bezier 的**第二个控制点→终点**这段切向决定，
  跟起点无关；箭头扎反方向时只挪 c2，不要交换起止点（batch23 fig70 panel b）。
- 三栏"同一构图转不同角"用 `panel(ox,oy,ang,tag)` + 局部点旋转：只旋转坐标、
  文字内容保持水平。但原书常把其中一栏重排（如圆标从箭头左侧挪到下方），
  这时给那一栏写显式坐标，别为它加参数（batch23 fig71 的 C 栏）。
- 虚线圆弧定量画法：读弧上三点解 `x²+y²+Dx+Ey+F=0` 得圆心与半径，再反算三点极角；
  `arc` 只按 CCW 扫，要画 CW 那段就把起止角对调，扫过的是同一批点（batch23 fig72）。
- 粗矢量线宽要跟原书量：`2.6pt` 在 ppi200 下比原书粗一倍，`1.9pt` 才对；
  同一图里"细轴 / 粗矢量"两档线宽差约 1.7 倍是这本教材的通例（batch23 fig70）。
- 发散/汇聚成对面板：同一套射线循环里只交换短段两端点顺序
  （`line(1.6d, 2.1d, mark:(end:">"))` ↔ `line(2.1d, 1.6d, ...)`），
  一个布尔参数出两图，中心符号 "+" 用两条短线、"−" 用一条加粗横线（batch20 fig61）。
- 斜投影 `S(x,y,z) = (y - k x, z - m x)` 里 **k 不能等于 m**：相等时整个
  `y = z` 平面被压到直线 `X = Y` 上，立方体底面隐藏边正好叠在 x 轴上，
  实线轴看起来变成点线。取 `k=.55, m=.42` 既破除简并又保留约 40° 的深度感
  （batch19 fig60）。

## 图型难度分级（batch1 样本）

- 易（一次过）：坐标轴 + 射线 + 若干标点标签（fig1、fig3 型）。
  要点：射线留短尾、箭头在末端、标签统一在点下方。
- 中（1–2 次重试）：圆 + 割线 + 虚线辅助构造 + 角弧（反演构造 fig2 型）。
  难点全在 arc 语义与重音符号，不在布局。
- 未验证：函数曲线、阴影区域、三维示意、照片类插图。预计曲线需
  `draw.bezier` 或折线采样；照片/灰度图不适合 CeTZ，应直接放弃。

## 选图效率技巧（batch2 新增）

- EPUB：解包后按 HSV 饱和度<0.12 且墨量 0.02–0.25 筛黑白线描，
  再目视；彩色 mesh/照片直接放弃，不要浪费重试次数。
  注意：教材类 EPUB 的插图常是 RGBA 透明底 PNG，墨量统计前必须先
  `Image.alpha_composite` 合成白底，否则判据全为 0 张命中（batch10）。
  图数 <100 时更省事的做法：全部缩成 220×170 缩略图 + 红字索引拼一张接触表，
  一次 Read 完成整库选型。
- PDF（哈希命名语料）：用 pymupdf 统计每页 `get_drawings()` 数且
  `get_images()==0`，取绘图数最高的页渲染，比盲翻页快一个量级。
  地图、数据散点照片类仍要放弃；框轴+稀疏脉冲类示意图可转。
- 数据图（脉冲/轨迹）重绘时先按原图目测列出峰位峰高表再下笔，
  均匀布峰一眼假，第一次必败。
- 扫描书（每页一张整页图）：`get_drawings()` 高不等于有矢量插图，
  框线公式页同样高分；排序后仍要整页渲染目视。Deaux 复数几何书的
  Fig.8/9/12/16 型"坐标轴+点线+角弧/轴箭"图都是易级，一次过。
- 找图页最快办法：`pdftoppm -r 60` 连渲染 10 页左右，PIL 横向拼成一张
  接触表（contact sheet）一次 Read 看完，图页的黑线团一眼可辨；
  再只对命中页渲染 130–150dpi 裁图。比逐页 Read 省 10 倍上下文。
- 扫描书全书图页地图：60dpi 灰度整书渲染 → 裁 6% 边 → `a<120` 二值化
  + 1 次膨胀 → `scipy.ndimage.label`，统计 bbox 高>18% 页高且宽>12% 页宽
  的连通块；文字页 glyph 块小不会命中。比 get_drawings 与接触表都准（batch6）。
- 元素密度门槛：双圆/三圆 + 8 个以上标签 + 虚线构造的图（Deaux Fig.30/33/
  34/50）在选择期就拒绝，不要浪费重试；双圆仅交于两点、线≤2 条的可转。
- 扫描书 PDF 页码 ≠ 印刷页码（Deaux 差 1）；按图号找页时先渲染确认页眉。
- 角弧起始角不必手算：`calc.atan2(p.y, p.x)` 反解后直接喂给 `arc(start:)`；
  角弧两端都靠射线上的点定位，改射线坐标后弧会自动跟手（batch8 fig25）。
- 连通域定位对小图（高<10% 页高）失效；退回半页缩略图目测→比例裁剪→
  Read 校验→二次微调，两轮即命中（batch8 p76/p91）。

## 放射状场线 / 花瓣箭头（batch24 fig75）

点电荷电场图这类"一个中心 + 8 条辐射箭头"的图，别一条条手画，写成
`spokes(中心, 起始角, tipR, baseR, r2, wid, tail)` 闭包，每个方向叠三层：
细轴（`r1→r2`）、填充三角花瓣（tip 在 `tipR`、底边在 `baseR`、半宽 `wid`）、
末端短虚线（`r2→r2+tail`）。正负电荷只差 tip/base 的先后：

- 正电荷朝外：`tipR > baseR`（如 1.72 / 1.30），花瓣小（wid≈0.17）。
- 负电荷朝内：`tipR < baseR`（如 0.30 / 1.28），花瓣胖（wid≈0.25–0.30），
  就是原书那种"粗箭头扎进中心"的花。

胖瘦只由 `wid` 与 `baseR` 决定，两者比值 > 0.3 就会糊成一朵花、看不见轴
（fig75 第一次目视失败就是这个）。起始角给每个电荷不同值（12°/20°），
八个电荷图并排时不会显得是复制粘贴。

- `draw.content` 里的 `\\` **不换行**，会原样印出反斜杠。多行说明文字拆成

## 新增硬坑（batch25）

- **`mark:` 绝对不能写进 stroke 字典**。`stroke: (thickness: 2.4pt, mark: (end: ">"))`
  会让 cetz 的 `styles.typ` 把 `mark` 当笔画属性递归 fold，报
  `maximum function call depth exceeded`（栈里全是 `fold-dict`），完全看不出真因。
  `mark` 必须是 `line()` 自己的命名参数。
- Typst 数组没有标量乘法：`u(45deg) * 1.35` 直接报错，要写
  `let sc = (p, k) => (p.at(0) * k, p.at(1) * k)`。
- 同一本书重复选图时先把 EPUB 解包缓存下来
  （`work/fleisch/x/OEBPS/images`，`sorted()` 文件名序号 = 新编号），
  选图用 3 列 × 430px 高的接触表一屏看 9 张，红字标 idx，一次 Read 定生死。

## 扇形/阵列箭头怎么画（batch25 fig78）

三排粗箭头组成的矢量场，别用"绕一个虚拟中心旋转"生成——原书每排的
倾角增量并不一致（下排近乎竖直、上排左右各歪 40° 以上），套公式一定走形。
逐条写 `arrow(尾x, 尾y, 角度, 长度)` 最省事：改一条不影响别条，
比对时按排扫一遍就能定位偏差。粗箭头要 3.4pt 才压得住原书的墨量。

## 椭圆环上的切向箭头（batch26 fig81）

`draw.arc` 只认正圆，透视磁场圈那种扁椭圆环上的切向箭头做不出来。
改成参数化点列喂给 `line(path: true)`：

```typ
let ell = (rx, ry, a0, a1, n) => {
  let pts = ()
  for i in range(n) {
    let t = a0 + (a1 - a0) * i / (n - 1)
    pts.push((cx + rx * calc.cos(t), cy + ry * calc.sin(t)))
  }
  pts
}
line(path: true, close: true, ..ell(rx, ry, 0deg, 360deg, 73), stroke: te)
line(path: true, ..ell(rx, ry, 148deg, 170deg, 7), stroke: te,
     fill: luma(18%), mark: (end: ">"))
```

- 整环用 0→360°、73 点、`close: true`；箭头只取 20° 左右的一小段，
  末端 `mark: (end: ">")`，切向自动就对，不用手算角度。
- **`mark` 的箭头要实心，这条线必须有 `fill:`**——只给 stroke 会画成空心 V，
  和原书的实心小箭头差一档（fig81 唯一一次重试）。
- 扁率取 `ry ≈ 0.265 rx`；0.30 以上环就"鼓"了。

## 开口 V 箭头（batch26 fig79）

有些书（Fleisch 的电荷射线图）箭头不是实心三角而是两笔细线。不必旋转矩阵，
按极角直接加减：`tip` 在半径 `rv` 处，两腿走 `sc(u(d ± 32deg), leg)`，
其中 `d = if out { a + 180deg } else { a }` 一个布尔切换朝内/朝外。
射线起点留 0.3 左右空隙、中心放 `$+$`/`$-$`，就是原书的断心画法。

## 斜面上的物块（batch27 fig83，3 次重试）

斜面 + 圆角物块 + 三力这张图连错三轮，结论：

- **圆角矩形不要用 `curve: (cyclic: true, tension: 78%)`**。CeTZ 的 cyclic 样条
  会把直边也拉弯，四个角出现缺口/鼓包，看起来像"断了"。正确做法是显式采样：
  四个角各 `for j in range(9) { a = 起始角 + j * 90deg / 8 }`，得到 36 个点，
  再 `line(path: true, close: true, ..pts, stroke: ...)`。想整体斜置就套一个
  旋转 `(p) => (p.x*cos - p.y*sin, p.x*sin + p.y*cos)`，先局部算再旋到页面坐标。
- **斜面那条线可以直接当 +x 轴**：一条 `line()` 加 `mark: (end: ">")` 就是轴，
  再单独画一条 x 轴会双重描边、且两条线永远对不齐（第二轮返工的原因）。
- 物块必须"坐"在斜面上：把整块的原点沿法向抬 `sc(ey, .52)`，
  即 `let C = sc(ey, .52); let P = (p) => add(C, p)`，所有点过 `P` 再落笔。

## Typst 数组的 `+` 是拼接（batch27 硬坑）

`sc(u(28deg), -4.05) + (0.05, 0.18)` 不会得到平移后的点，而是拼成四元组，
报错 `Failed to resolve coordinate system: (-3.57, -1.90, 0.05, 0.18)`。
一律用自定义 `let add = (p, q) => (p.at(0) + q.at(0), p.at(1) + q.at(1))`。
标量乘法同理不存在，需要 `let sc = (p, k) => (p.at(0) * k, p.at(1) * k)`。

## anchor 必须带连字符（batch27 硬坑）

`anchor: "south west"` 直接 panic `Anchor 'south west' not in anchors`。
合法值只有 `"north-west"` / `"south-west"` / `"north-east"` / `"south-east"` 等
连字符形式。多行文字仍然只能拆成多个 `content()`（`\` 会被原样打印）。

## 旋转坐标系的两种分解（batch27 fig84）

同一矢量在 (a) 未旋转系画成矩形、在 (b) 旋转系画成平行四边形，一次 `frame()`
闭包画两遍即可，别写两份代码。primed 分量用**投影**算而不是手摆坐标：
`let a = T.at(0)*ex.at(0) + T.at(1)*ex.at(1)`，`let Cx = sc(ex, a)`，
则 `0→Cx` 是 `A'_x` 分量箭头、`Cy→T` 与 `Cx→T` 是虚线辅助边。
这样矢量端点、分量、辅助线三者天然闭合，改角度不用重算。

## Typst 数学：bar 不是上横线（batch30 硬坑）

`$bar(a)$` 在 Typst 里是**绝对值**，渲染成 `|a|`；书里的矢量上横线要用
`$overline(a)$`（`macron(a)` 也有上横线但太短，压不住字母）。
`$ar(a)$` 直接报 `unknown variable: ar`——Typst 不认 LaTeX 宏名。
`over` 也不是关键字（`$1 over nu_0$` → `unknown variable: over`），分式写 `$1/nu_0$`。

## 斜线分式 vs 堆叠分式（batch30）

`$-a/2$` 会被排成上下堆叠的分式，和书里的 `−a/2` 行内斜线写法不符。
要斜线形式用关键字 `slash`：`$-a slash 2$`。
反过来，书里真是堆叠分式（如 `1/ν₀` 画成上下）时就用 `$1/nu_0$`。

## 周期波形的"半齿"处理（batch31 ft03）

锯齿/三角波画到右边界时，最后一齿常只露出一半。Cetz 没有裁剪框，
**不要画整齿再指望它被页面切掉**（切出来的斜率和位置都不对，本会话因此返工一次）；
正确做法是按同一斜率手算截断段的两个端点，单独一条 `line()`：

```typ
let P = 2.6
let hh = 1.5
for k in range(-2, 3) {          // 完整齿
  let a = k * P - P / 2
  line((a, -hh), (a + P, hh), stroke: t)
  line((a + P, hh), (a + P, -hh), stroke: t)   // 竖直回落
}
line((6.5, -hh), (8.4, 0.69), stroke: t)       // 截断齿：0.69 = (8.4-6.5)*2*hh/P - hh
```

## Typst 数学里的插值语法（batch32 ft18）

## batch64：文字标签和"墨框极值"才是过不了关的真凶

三张图（dt72 邻域示意、dt11 小变形、dt40 交叉弧）都过了，但 dt11 卡了四轮，
原因不在曲线而在**文字**。曲线本身用 batch62 的粗读+吸附一次就好。

### 单向指标对文字意味着"宁小勿大"

`ov2.py` 只算 渲染墨点→源图墨点 的最近距离，反向不计。于是：

- 渲染字偏小：笔画仍落在源字笔画上，距离≈0，几乎不扣分；
- 渲染字偏大或整体偏移：多出来的部分周围没有源墨，均值直接爆。

dt11 的 "in ℝ²" 源宽 68 px、6.4pt 渲染出 76 px（宽 12%），但 cap 高 23 px 是对的。
这套书的正文字体比 Libertinus 扁窄，改字号只能对上一个方向；
`Times New Roman / Arial Narrow / Tahoma` 都试过，整串宽度基本没差别（Arial Narrow 系统里没装）。
结论：字号按**高度**定，位置对准，宽度差留给单向指标吸收。别去追字体。

### 渲染墨框必须罩住源图墨框

对齐是"按宽度比算统一缩放 + 平移搜索"。我少画了源图最外沿的极值点
（左曲线尖端停在 y=21，源图墨到 y=16；底端停在 275，源图到 281），
渲染框就比源框矮，缩放比失真，全图垂直偏 6 px —— 看着都对，均值却卡在 1.0 以上。

### chain() 的两条使用注意（batch62 方法补录）

- `need=2` 跳过墨迹断掉的列，否则 `pick=0` 会跳到下边界，拉出 216 px 的横弦、折线自交

## batch65：文字撑墨框时，整张图被百分比级拉伸

三张都过：`dt16-ball` 0.41 px（圆拟合 + 割线 + 箭头 + 两点）、`dt19-bend` 0.33 px（矩形框 + S 曲线 + 两个大括号）、

- **`sc` 只看墨框宽度，所以谁撑住墨框极值，谁就决定全图缩放。** 如果最左/最右的墨是**文字**（很常见：
  标签总在图形外面），而字体和原书不一致，渲染墨框宽度和"我按源图坐标画的几何"就对不上，
  `sc` 会把整幅几何做一次百分比级缩放。dt5 实测 1.17 %：左竖线画在源图 x=58 落点 57，右竖线画在 401 落点 404。
  1 % 在 700 px 宽的图上就是 7 px 漂移，mean 直接从 0.79 炸到 1.36。
- **修法是把渲染当一次仿射拟合**：取两条已知的水平/竖直线段，量出 `converted = c + k * drawn`
  （两个点解两个未知数），再反解 `drawn = (target - c) / k` 重画。dt5 改完 1.36 → 0.79。
  只有当改动的元素不撑墨框极值时 k 才稳定；动了极值标签要重量。
- **`m11.py` 那一族量标签的脚本算错了**：`box(rr)` 给的是裁剪窗口内的相对坐标，脚本当绝对渲染坐标用，
  每个窗口都少加 `(rx0 - BR[0]) * sc`。batch64 靠它调标签其实只在"同窗口内相对比较"上勉强能用。
  现在换 `work/batch65/meas.py`：先按 `ov2.py` 同样的方式把渲染重采样到源图尺度，再取源图窗口内的渲染像素 bbox，
  src 和 render 都在源图坐标系，能逐元素对比。后续批次直接复制 `meas.py`，别再复制 `m11.py`。
- **成段的公式不要描点**。dt5 右侧两行 `$phi(0) = x$`、`$psi(0) = y$` 原本打算逐笔提取，
  最后用 `content(pos, anchor: "west", [$ϕ(0) = x$])` 排出来，第一行分区域 mean 只有 0.35，比描点省事得多。
- **`$phi$` 和 `$ϕ$` 不是一回事**：Typst 的 `$phi$` 给圈式 φ（23.6×26.2 源像素），
  这套书的 $phi$ 是竖笔穿过的直立式（18×33，长宽比 0.55）；直接写 Unicode `$ϕ$`（U+03D5）才接近。
  `$varphi$` 不是合法标识符，编译报 `unknown variable`。
- **大括号可以按行提取**：印刷体 `}` 的每一行只有一段墨，x 是 y 的单值函数，

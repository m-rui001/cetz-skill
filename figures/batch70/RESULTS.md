## tr.py：把上一轮的追踪器变成通用工具

`load / mask_of / runs / col / trace / comps / blobs / sub`。
`trace(start, heading)` 就是 batch68 的海龟法。`blobs(k=7)` 直接给出膨胀后残留的实心块
（点、箭头最宽处），`(x, y, n, x0, x1, y0, y1)`，半径用 `r = 3 + sqrt(n/pi)` 反推，dt25/dt45 都准。

## 本轮新踩的坑：标签没对准源图中心，会让整幅几何放大 1–2 %

dt25 第一版 mean **1.34 px**，overlay 上圆整圈均匀地偏外（magenta 包着 cyan）。
不是追踪的问题（追踪折线 bbox 388.6×395.1，源笔画中心线应为 386×394，误差 <1 %），
而是 **`g(x)` 标签我按目测放在 x=48，源图它的墨心是 x=43**。
墨框左沿由标签撑，标签右移 5 源像素 → 渲染墨框宽度少 1.1 % → `ov2` 的 `sc` 大 1.1 % →
整幅圆被等比放大，且因为是**宽度**定标，垂直方向就表现为"圆太高"（ar 1.163 vs 1.136）。
把三个标签改成源图墨框中心（43,159.5 / 246,171.5 / 406,160.5）后 1.34 → **0.43 px**。

推论（和 batch68 的"逐字定位"是同一条规律的两种表现）：
**凡是撑住墨框极值的文字，位置必须按源图墨框中心给，不能按目测基线给。**
判据很简单：先 `comps()` 量出该标签的 `x0..x1 / y0..y1`，取中心，别猜。

## 延后 / 不适合

- **dt79（球 + 两条经线 + 赤道虚弧 + N/S 点）延后**。它是"所有曲线都交于两个极点"的拓扑：
  极点处 outline / 两条经线 / 赤道至少 4 条弧共点，海龟的"直行"规则在这里没有唯一解。
  实测：从最左点起追第一圈拿到 `CLOSED` 159 点（正好是外轮廓，周长 1113 px ≈ 2π·179），
  但按 ±4 膨胀清除后剩余墨迹只剩 x≈21 处的 1–2 个点，说明其余弧在清除时被连带吃掉，
  无法用"追一条清一条"的循环分解。
  **改法已明确**：这类图不该自由追踪，应该走极点球面模型——外轮廓用 `circle`
  （实测 bbox 12..371 / 54..415 → 中心 (191.5,234.5)，rx 179.5 / ry 180.5，近圆），
  极点实心点已量出 (187.3,61.6) 与 (196.4,407.3)，每条经线 = 过 N、S 与自身最左/最右点的**圆弧**（三点定圆），
  赤道前半是同理解出的椭圆弧，后半 12 段虚线 `comps()` 已天然分开（y 190..218，逐段画）。
  留专门一轮做，不占用本批额度。
- **dt35（圆 + 左侧实心点 + `L_i` 标签）不适合**：源图本身被裁切，墨迹右边缘 x=295 已顶到图宽 300 的边界，

- dt57 / dt68 / dt75 / dt81 墨迹占比 0.20–0.39（灰面/照片感），按既定判据不碰。

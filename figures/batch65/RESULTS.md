## 本批最大的一条新规律：墨框极值落在文字上时，几何会被整体拉伸

`ov2.py` 的缩放系数 `sc = 源图墨框宽 / 渲染墨框宽`，是**纯宽度**决定的，然后做一次平移搜索。
只要渲染图的墨框极值（最左/最右）是由**文字**撑出来的，而文字的实际字宽和源图不一致（几乎必然不一致，
书的数学字体比 Computer Modern 宽），渲染图的墨框宽度就和"我按源图坐标画出来的几何"脱钩，
`sc` 会带着整个几何做一次百分比级的缩放。dt5 上实测到 1.17 %：
左竖线画在源图 x=58，落到 x=57；右竖线画在 x=401，落到 x=404。
1 % 的横向漂移在 700 px 宽的图上就是 7 px，直接让 mean 从 0.79 涨到 1.36。

对策（已验证）：把渲染当成一次仿射拟合，先量出
`converted = c + k * drawn`（取两条已知水平/竖直线段的 drawn 与 converted 值解出 c、k），
再反解 `drawn = (target - c) / k` 重画一遍。dt5 用这个式子改完，mean 1.36 → 0.79。
注意 k 只在我改动"非极值"元素时稳定；如果动了撑墨框的那几个标签，要重新量一次 c、k。

## 工具修正：`m11.py` / `m.py` 系列量标签的脚本原来算错了

`box(rr)` 返回的是**裁剪窗口内**的相对坐标，而脚本按绝对渲染坐标去换算，等于每个窗口都少加了
`(rx0 - BR[0]) * sc`。之前 batch64 用它调标签时，绝对量是错的、只有同窗口内 src/render 的相对差勉强能用。
现在换成 `meas.py`：先把渲染按 `sc` 重采样到源图尺度（和 `ov2.py` 完全一致），再把落在源图窗口内的渲染像素
直接取 bbox，src/render 两边都在源图坐标系里，可以逐元素对比。这个脚本值得复制到后续每个批次目录。

## 提取方法回顾（本批用到的）

- dt16：圆用代数最小二乘拟合（先剔掉横线带 `y∈[206,226]` 和两个实心点的邻域），
  半径 126.0、圆心 (330.7, 189.0)，`frac<3px = 0.883`；横线源图本身有 0.5° 倾角，照画。
- dt19：`gen19.py` 里三样东西——
  1) S 形曲线按列 `chain`（候选 run 长度 ≤14，与上一列中心差 >12 就丢弃），829 列全部接上、无断点；
  2) 两个大括号按行取 run 中心（每行只有一段，所以 x 是 y 的函数），每 2 行采一个点，
     首尾各补一个端点，直接 `line(path: true)` 画折线，128 px 高的括号拟合得很好；
  3) 矩形框五条线各自在两端量中心，顶线有 2 px 倾角也照画。
- dt5：全是直线段和文字，没有曲线。四段箭头按行/列量中心；箭头帽源图是"实心三角"（竖着的）和
  "粗 V"（横着的），统一用 `fill: black` 的 `>` 帽，量出 length/width 换算成 pt。
  两行公式**不描点**，直接 `content(... [$ϕ(0) = x$])` 排出来，比逐笔描省事得多，
  mean 只贡献 0.35（第一行）。

## 字形取舍

- 源图的 $\phi$ 是"竖笔穿过"的直立式（18×33 px，长宽比 0.55）。Typst 的 `$phi$` 给的是圈式 φ（23.6×26.2），
  形状不对；直接写 Unicode `$ϕ$`（U+03D5）能拿到接近的直立式。`$varphi$` 在 Typst 里不是合法标识符，会编译报错。
- 字号按 cap height 定：`pt ≈ cap_px * 0.2736`（S=148 时）。dt5 的 X 高 29 px → 8 pt；
  dt19 的 X 高 23 px → 6.3 pt。
- 单向指标仍然成立：字偏小几乎不扣分，偏大或偏位才炸。所以拿不准时取小。

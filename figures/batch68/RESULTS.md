## 本轮最大的收获：交叉闭曲线用"带惯性的海龟追踪"分解

dt21 是两条互相穿过 4 次的闭曲线，`chain()`（按列取 run）和射线法都会串台。
`trace21.py` 里的追踪器一次就分对了：

```python
def trace(start, heading, R=7.0, halfwin=55.0, hsm=0.55):
    # 每步：在以 cur 为心、半径 R 的圆上，取 heading±halfwin 内所有落在墨上的角度
    # 按连续性切成若干区间，选"中点最接近正前方(0°)"的那个区间
    # 新区间中点 = 新航向，cur += R*u(θ_mid)，heading 做 0.55 的指数平滑
```

要点：
- **只看前方 ±55°** → 到交叉点时天然"直行"，不会拐进另一条曲线；
- **区间中点 ≈ 笔画中心线**（墨带在半径 R 圆上截出的弧，其中心就是中心线交点），所以不用骨架化；
- 起点必须落在笔画中心：用列 run 中心取极值列（X 取最左列 45，Z 取最右列 566）；
- 终止：回到起点半径 0.9R 内即判定闭合。X 96 点、Z 233 点，均闭合。
- 星号/实心点会让局部墨带变宽，但因为只看方向不看法向，中点仍准。

这条比之前"极坐标 first-hit 分箱"通用得多：后者要求曲线对某点是凸的，海龟法无此限制。

## 文字撑极值 → 逐字定位（第二次踩，这次有解法）

dt21 第一版把 `#(X∩Z) = 4` 当一个 `content` 居中，mean 3.14 px。原因：
`ov2.py` 的缩放比 s 只由**两幅墨框宽度比**决定。整串文字比原图窄 30%（原图靠宽字距撑到 208 px，
Typst 排出来只有 144 px），于是 s 偏大 4%，**全部几何被等比放大 4%**，overlay 上曲线两侧都出 magenta。

解法：把公式拆成 8 个 `content`，每个用原图里该字符的实际中心定位（`#` 753.5,152.5 / `(` 772,156 /
`X` 795.5 / `∩` 824.5 / `Z` 853.5 / `)` 873 / `=` 908.5 / `4` 942.5），字号 6.0 pt。
墨框立刻对上：ar 3.378/3.346，mean 3.14 → 0.37。

推论：**只要文字参与墨框极值（在图的最左/最右/最上/最下），就必须逐字定位**，
不能指望整串居中；否则 s 被带偏，几何怎么调都过不了 1 px。

## 其它

- `∩` 在 Typst 里：`$X cap Z$` 会被当代码解析（unknown variable: cap）；直接写 unicode 会被 Windows
  GBK 默认编码写成非 UTF-8。可用写法是 markup 转义 `\u{2229}`，并且生成脚本以 `encoding='utf-8'` 写文件。
- 实心交点：`ndimage.binary_erosion(m, np.ones((7,7)))` 后取连通块质心，再**吸附到已追踪出的 X 折线最近点**
  （<14 px 才收），4 个点全部命中，比直接拿质心准。
- 笔画宽度实测中位 5 px → 1.05 pt，与既有换算（1 pt ≈ 5 源 px）一致。
- dt66：箭头有实心楔形和开口 V 两种，楔形用凸包 + `line(close: true, fill: black, stroke: none)`，
  开口 V 用两条 `path: true` 线段（0.95 pt）。`circle` 必须 `circle(point, radius: r/S, ...)`。
- 虚线（dt39 结论沿用）：`stroke: (dash: ...)` 相位对不上必炸，逐段画。
